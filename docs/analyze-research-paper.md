# Analyze Research Paper｜中文介绍与使用指南

> 不止提炼论文摘要，更要读懂研究动机、技术机制、实验证据，并将可迁移的方法转化为值得验证的科研 Idea。

[返回仓库首页](../README.md) · [查看 Skill 执行规则](../analyze-research-paper/SKILL.md)

## 1. 技能定位

`analyze-research-paper` 面向科研学习、组会汇报、论文复现及后续选题。它把 AI 设置为**论文阅读专家、审慎的审稿人、复现导师与研究 Idea 顾问**：从“为什么提出这个方法”一直追问到“什么实验证明它有效”“换到我的模型中是否还成立”。

默认用中文解释，保留必要英文术语。尤其适用于计算机视觉、点云、Few-shot Segmentation、目标检测和深度学习方法研究，同时可根据论文类型调整分析结构。

## 2. 适用场景

- **快速判断阅读价值**：短时间抓住问题、关键思想、主要贡献和局限。
- **深度技术学习**：逐层解释 Backbone、模块、公式、损失函数、训练与推理流程。
- **实验审查**：比较 Baseline、其他模型、消融实验、效率和鲁棒性，核查对照条件。
- **科研组会准备**：整理可讲解的技术脉络、结论、疑点和导师可能追问的问题。
- **复现和创新探索**：梳理复现条件，提炼可迁移机制并设计低成本验证实验。
- **多篇对比**：在相同指标和数据协议下构建技术对照表，挖掘共同问题与互补设计。

## 3. 核心能力

| 能力 | 主要工作 | 典型产出 |
| --- | --- | --- |
| 问题与背景 | 定义任务、研究痛点和已有方法缺口 | 一句话总结、研究背景、问题链条 |
| Baseline 与创新 | 区分原始模型、相关工作、Backbone 和新增机制 | 贡献对照、架构差异 |
| 方法解析 | 理解顶层设计、模块数据流、公式与训练细节 | 分步骤方法讲解、技术机制解释 |
| 结果审查 | 核对数据集、指标、主结果、消融与效率 | 有来源的对比表、公平性分析 |
| 复现准备 | 识别代码、数据、配置、算力与评价方法 | 复现清单和潜在风险 |
| Idea 迁移 | 对接目标模型，提出改进与验证方式 | 2–4 个具体假设、插入位置、最小实验 |

## 4. 输入与输出

**建议提供：**

- 论文 PDF 最佳，也可提供 arXiv、DOI、官方论文页或正文。
- 目的：五分钟速读、深读、准备组会、准备复现，还是寻找创新点。
- 最关注的内容：方法公式、Baseline、Backbone、消融、可迁移模块等。
- 若需要迁移，请说明目标任务和模型，例如 PTv3、PointSLA、S3DIS 或 ScanNet200。
- 如果有官方仓库、补充材料和配置，可一并提供。

**通常得到：** 论文档案、问题与动机、方法结构、定量对比、批判性评价、复现注意事项，以及可迁移的科研 Idea 和下一步实验建议。具体深度以指定模式为准。

## 5. 使用步骤

1. **提供论文**：尽量上传完整 PDF，避免仅凭标题或摘要下结论。
2. **指定模式与重点**：默认深读，也支持速读、组会 Reviewer、代码复现、Idea 迁移和多篇对比。
3. **提出进一步问题**：可以追问某个公式、模块、数据划分或创新想法；需要时再让 AI 整理复现步骤或实验矩阵。

在支持个人 Skills 的 ChatGPT 中可使用 `@analyze-research-paper`，在支持命名 Skill 的编程 Agent 中也可按其语法调用 `$analyze-research-paper`。

## 6. 使用示例

**示例 1｜全面精读一篇论文**

```text
使用 $analyze-research-paper 深度阅读我上传的论文。
请按研究背景、任务、Baseline、研究缺口、顶层思想、
方法模块与公式、实验结果、局限性和科研启发组织分析。
给出作者方法相对直接 Baseline 的量化提升，并标注表格出处。
```

**示例 2｜重点分析实验与 Backbone**

```text
使用 $analyze-research-paper 重点审查这篇论文的实验。
分别整理相同 Backbone 下的 Baseline 对比、
不同 Backbone 或其他方法的比较、消融与效率结果。
核对数据集划分、指标、训练设置和公平性，
对于论文没有报告的结果明确写“未报告”。
```

**示例 3｜迁移到点云分割研究**

```text
使用 $analyze-research-paper 的 Idea 迁移模式。
我研究 Few-shot Point Cloud Segmentation 和 Point Transformer。
请从论文中提炼 2–4 个可复用技术机制，
分别说明适用问题、接入位置、需要修改的模块、
计算成本、可能失败的条件，以及 1–3 天可验证的小实验。
不要把推测写成已证实的实验结论。
```

**示例 4｜导师组会与复现准备**

```text
使用 $analyze-research-paper 帮我准备 15 分钟组会介绍。
先形成适合讲述的技术逻辑，再提出 5 个导师可能追问的问题。
同时给出复现所需的数据、代码、环境、关键超参数和评估流程。
没有原文证据的参数或结果不要自行补齐。
```

## 7. 使用建议与边界

- **完整论文优先**：只有摘要或截图时，应明确分析范围；不能杜撰公式、图表或论文贡献。
- **区分证据类型**：将“论文事实”“计算得出的差值”“AI 推断”“未经验证的研究建议”明确分开。
- **保持对照公平**：mAP、mIoU、FLOPs、参数量及其统计口径要准确；不同数据划分或训练配置不宜直接当作受控改进。
- **科研 Idea 需要检验**：新模块组合不等于创新成立，应先验证机制、兼容性、资源开销及负面结果。
- **复现不等于已执行**：Skill 可以给出路径和检查清单，但未实际运行的代码与实验不能声称已经验证。
