# Beautiful Web Design｜中文介绍与使用指南

> 让 AI 像一位注重视觉质量、真实交互和代码维护性的前端设计师，帮助你设计、开发、审查和改进 Web 页面。

[返回仓库首页](../README.md) · [查看 Skill 执行规则](../beautiful-web-design/SKILL.md)

## 1. 技能定位

`beautiful-web-design` 面向网页和 Web 应用的设计开发任务。它会先理解产品定位、目标用户和关键操作流程，再确定视觉语言、响应式布局和可复用组件，最终检查实际交互和交付质量。

它既能从零设计页面，也适合接手已有 React 项目进行渐进式优化。对于 NestFind 这样的移动端优先产品，重点不只是“页面好看”，还包括搜索、筛选、反馈、导航和异常状态是否真正可用。

## 2. 适用场景

- **从零搭建**：产品首页、登录注册、租房列表、详情页、仪表盘、个人作品集。
- **UI 视觉改版**：调整配色、字体、间距、卡片、图标和视觉层级。
- **移动端适配**：手机优先，再拓展平板与桌面，检查触控与滚动体验。
- **组件与交互**：设计可复用的 React 组件，以及加载、空数据、错误、成功等状态。
- **体验审查**：检查易用性、可访问性、表单与导航，提出具体修复建议。

## 3. 核心能力

| 能力 | 主要工作 | 典型产出 |
| --- | --- | --- |
| 需求与页面规划 | 确定用户旅程、必要页面、功能约束 | 页面清单、交互流程、设计方向 |
| 视觉系统 | 统一色彩、排版、间距、圆角与组件状态 | 设计规范、布局与组件方案 |
| 前端实现 | 在现有技术栈中完成响应式界面 | React / HTML / CSS 等代码改动 |
| 真实交互 | 连接状态与数据，处理反馈及异常 | 可操作的搜索、筛选、表单等 |
| 质量审查 | 检查桌面/移动端、交互、可访问性 | 问题清单、修复内容、验证说明 |

## 4. 输入与输出

**建议提供：**

- 产品名称、目标用户、希望实现的页面或功能。
- 技术栈与已有项目位置（如 React + TypeScript）；有代码时请提供仓库或文件。
- 偏好的风格（颜色、参考网站、移动端优先等）。
- 必须保留的旧功能，以及希望修改的范围。
- 如果是改版，可附当前页面截图和最不满意的地方。

**通常得到：** 设计方向与关键决策、页面/组件实现或修改建议、交互状态、检查结果及后续改进事项。只要求方案时不会擅自改代码。

## 5. 使用步骤

1. **指定技能和目标**：例如“使用 `$beautiful-web-design` 设计 NestFind 移动端房源列表”。
2. **明确约束**：说明现有代码、配色、是否允许修改功能、移动端要求。
3. **检查并迭代**：要求展示实现内容，检查搜索、筛选、空数据和窄屏效果，再针对问题微调。

在支持个人 Skills 的 ChatGPT 中也可通过 `@beautiful-web-design` 指定；具体调用语法取决于环境和安装方式。

## 6. 使用示例

**示例 1｜从零设计移动端页面**

```text
使用 $beautiful-web-design 为 NestFind 智能租房平台设计移动端首页。
采用蓝白现代风格，包含城市选择、搜索框、预算筛选和房源卡片。
先说明信息层级与布局思路，再实现响应式 React 页面。
```

**示例 2｜优化已有页面并保留功能**

```text
使用 $beautiful-web-design 优化当前 NestFind 房源列表页。
保留搜索、预算筛选、水电类型筛选、排序和结果统计逻辑。
重点提升手机端排版、交互反馈和无结果时的用户体验。
请说明你实际修改了什么，以及哪些功能已经验证。
```

**示例 3｜视觉与可用性审查**

```text
使用 $beautiful-web-design 审查我上传的网页截图和对应代码。
检查视觉层级、字体、间距、颜色对比、触控区域和响应式设计。
按严重程度列出问题，给出最小修改方案，暂时不要写代码。
```

**示例 4｜建立小型设计规范**

```text
使用 $beautiful-web-design 为个人项目整理一套可复用的设计规范。
包括配色、字体层级、间距、按钮、卡片、输入框及加载/空状态。
兼顾 React 组件复用和移动端开发。
```

## 7. 使用建议与边界

- 先说明希望获得**设计方案**、**可运行代码**，还是**代码审查**，避免范围过大。
- 改造已有项目时明确哪些业务逻辑必须保留；不应为了视觉效果破坏真实功能。
- 参考图片可以指导视觉风格，但不能直接证明页面在手机或浏览器里可用。
- Skill 会在有工具和项目的情况下尝试检查真实运行；没有实际测试时，不应声称已经完成浏览器验证。
- 若涉及后端接口、真实数据、登录与支付，应分清演示 UI 与已接通的生产功能。
