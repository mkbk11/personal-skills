# Check Assignment｜中文介绍与使用指南

> 像一位认真、严格但不代写的助教，帮你发现作业中的语法、逻辑、推导、代码和格式问题。**只指出问题与修改方向，不直接润色、扩写或替你完成作业。**

[返回仓库首页](../README.md) · [查看 Skill 执行规则](../check-assignment/SKILL.md)

## 1. 技能定位

`check-assignment` 是“**只检查、不代改**”的作业复核工具。它会尽可能对照教师给出的题目、评分标准和提交要求，检查学生**已完成的作业**，帮助学生理解错误并自主修改。

默认用中文反馈，也能检查英文作业的语法和术语。不以生成更漂亮的答案为目标，而是保留原有内容、思路和作者身份。

## 2. 适用场景

- **英语或中文报告**：语法、拼写、术语、逻辑衔接、引用和格式。
- **数学/统计作业**：公式条件、推导过程、符号、计算、假设检验和结论解释。
- **Python/Java/C++ 程序作业**：代码逻辑、输入输出、边界条件、异常处理和题目要求。
- **爬虫/数据作业**：Selenium、正则表达式、数据提取、SQLite 与可复现性。
- **AI/实验报告**：实验设计、Baseline 公平性、指标含义和数据结果一致性。
- **PPT、Notebook 和提交文件**：内容覆盖、页数/时间、图表清晰度、文件规范。
- **提交前复查**：根据之前的问题清单，检查你自己修改后的版本。

## 3. 核心能力

| 能力 | 检查什么 | 输出什么 |
| --- | --- | --- |
| 作业要求核对 | 是否覆盖教师明确要求的题目、过程、文件和格式 | 满足 / 部分满足 / 缺失 / 无法判断 |
| 语法与表达 | 中英文语法、标点、术语不统一、容易误解的表述 | 定位问题、相关规则、改进方向 |
| 逻辑与推导 | 假设、公式转换、计算步骤、结论与证据是否一致 | 最早可疑步骤、原因、自检方法 |
| 代码与数据 | 功能实现、正则、边界输入、异常、输出与任务一致性 | 静态问题清单和测试建议 |
| 学术与格式 | 引用、图表、单位、文件命名和提交要求 | 提交前检查清单 |
| 二次复查 | 用户自主修订后问题是否仍存在 | 已解决 / 部分解决 / 仍存在 |

## 4. 输入与输出

**最好同时提供：**

1. **作业要求或评分标准**：老师的原题、Rubric、格式/字数/页数/时间限制。
2. **你已写好的作业**：PDF、Word、PPT、Notebook、代码文件、LaTeX、截图或粘贴正文。
3. **检查范围**：全面检查，或只查语法、推导、代码、提交格式。
4. **特别担心的地方**：例如“老师喜欢问正则表达式的细节”或“担心假设检验的 p-value 过程”。

**通常得到：** 已检查范围、要求覆盖表、按高/中/低严重程度排列的问题清单，以及“为什么有问题”“建议检查什么”“如何自己验证”的说明。

**不会得到：** 润色后的全文、扩充的新段落、直接替换的正确答案、补完的推导或整份重写代码。

## 5. 使用步骤

1. **上传题目和作业**：老师原始要求最重要；没有题目也可以先做一般检查，但无法判定是否完全覆盖要求。
2. **选择检查模式**：速查、全面检查（默认）、仅语法、数学/统计过程、代码静态检查、提交前检查。
3. **阅读问题清单并自行修改**：按严重程度先改正确性和必做项，再处理逻辑、语法与格式。
4. **提交自己修改的新版本**：让 Skill 按原有问题编号进行二次复查。

在已安装该 Skill 的 ChatGPT 中可输入 `@check-assignment`；在支持对应语法的 Codex 等环境中也可使用 `$check-assignment`。

## 6. 使用示例

**示例 1｜按老师要求全面检查**

```text
使用 $check-assignment 检查我上传的作业。
第一个文件是教师的作业要求，第二个文件是我完成的答案。
请逐项核对要求、内容完整性、语法、逻辑和提交格式。
只给问题位置、严重程度、原因和修改方向。
禁止直接润色、扩写、改写或补全我的答案。
```

**示例 2｜数学与统计推导检查**

```text
使用 $check-assignment 检查这份参数估计作业。
重点检查 MOM、MLE 的推导步骤、变量条件、公式变形、
仿真结果和结论是否一致。
请指出最早出现问题的步骤及其原因，
给我独立检查的提示，不要替我完成正确推导。
```

**示例 3｜只检查英文语法**

```text
使用 $check-assignment 只检查这篇英文作业的语法。
标记主谓一致、时态、冠词、介词、标点和术语问题，
指出位置、规则和我应检查的方向。
不要输出修改后的句子，也不要润色写作风格或增加内容。
```

**示例 4｜爬虫与代码作业检查**

```text
使用 $check-assignment 静态检查我的 Python 作业。
作业要求是 Selenium 爬取澳门巴士数据，
使用正则表达式提取，并保存到 SQLite。
核对程序是否满足要求，检查正则、函数逻辑、
异常处理、数据存储和老师可能追问的代码细节。
不要运行不明代码，不要修改代码文件或提供完整修正版。
```

**示例 5｜提交前与二次复查**

```text
使用 $check-assignment 检查我自己修改后的最终版本。
请沿用上一轮的问题编号，标注已解决、部分解决或仍存在。
再核对教师要求的文件名、页数、图表、引用和提交格式。
只报告剩余问题与自检办法，不要直接替我修改文件。
```

## 7. 使用建议与边界

- **最重要的限制：只检查，不代改。** 不生成可直接替换的文章、公式推导、代码或新增例子。
- **尽量上传题目原文**：没有教师要求时，不应猜测“必须包含哪些内容”。
- **检查有范围限制**：没看到的页面、没运行的代码、未提供的数据要明确标注“无法核实”。
- **不要把风格偏好当语法错误**：只有确实影响语法、准确性、逻辑或要求时才提出。
- **问题不等于判定不及格**：高/中/低只是修改优先级，不是教师真实评分。
- **AI 检测不可作为定论**：不能根据语言风格可靠断定抄袭或 AI 生成。
- **遵守课程政策**：若教师限制使用 AI 工具，应按课程要求使用，不应借助工具绕过规定。
